# 家庭电脑续作提示词

请继续开发这个项目。项目是一个中文浏览器大富翁游戏，代码位于 Gitee 仓库，使用 pnpm workspace + TypeScript + React/Vite + Socket.IO。

## 开发目标

这是“新城地产局”在线大富翁：

- 普通联机支持 4-8 人。
- 支持 1 名真人挑战 3 名 AI。
- 只需要支持一局进行中的游戏，不做多房间集群扩展。
- 游戏网站是主产品，另有公开开发进度网站。
- 视觉方向是经典纸质桌游风：米黄色纸张、木质棋盘、印刷色板。

## 当前已经完成

- 游戏大厅、房间码、准备和开始游戏。
- 简化版和复杂版两种模式。
- 掷骰、移动、经过起点奖励、地产购买、租金、税费、事件格。
- 放弃购买后的轮流拍卖。
- 复杂版街区垄断、均衡建房和租金倍率。
- 监狱、对子尝试、保释和第三次强制保释。
- 地产抵押：无房屋地产可以获得价格 50%，抵押期间不收租。
- 银行贷款：200/500/1000 三档，每轮累计 20/60/140 利息，每人同时最多一笔，可一次性还清。
- 随机事件：个人事件、全城事件、现金最少者救助事件。
- 破产与债务处置：支付不足时自动清算地产，欠租转给收租者，税费/事件不足时地产回到银行，仍不足则破产。
- 单人 AI：AI 会掷骰、购买、放弃购买、拍卖、处理监狱和结束回合。
- 公开进度网站和 PostgreSQL 留言 API。
- Ubuntu Docker Compose、Nginx、游戏服务、进度站和数据库部署配置。

## 重要开发约束

- 先阅读项目内 `AGENTS.md` 和上述文档。
- 规则逻辑必须放在 `packages/game-rules`，不要把权威规则写进 React 组件。
- 服务端负责资金、骰子、事件和回合裁定，客户端只发送操作请求。
- 优先复用现有结构，不做无关重构。
- 修改前先检查当前 Git 状态，不覆盖用户已有改动。
- 使用 `apply_patch` 编辑文件。
- 完成后至少运行：
  - `pnpm test`
  - `pnpm typecheck`
  - `pnpm build`
  - `git diff --check`
- 不要提交真实的 `.env`、数据库密码或服务器密钥。

## 建议下一步

优先实现玩家交易第一版：

1. 现金换地产。
2. 地产换地产。
3. 现金加地产的组合交易。
4. 交易由发起方创建，目标玩家接受或拒绝。
5. 双方确认后由服务端一次性完成资产交换。
6. 抵押地产、建有房屋的地产暂时不能交易。
7. 交易过程中不能让任何玩家出现负现金。
8. 交易完成后广播给全房间并写入城市动态。

交易实现完成后，再进行浏览器多客户端测试，然后再设计城市议会投票。赌场暂时不要实现，只保留在规则文档的后续规划中。

## 本地运行

在仓库根目录执行：

```sh
pnpm install
pnpm dev:server
pnpm dev:game
pnpm dev:progress
```

默认地址：

- 游戏网站：`http://localhost:5173`
- 开发进度网站：`http://localhost:5174`
- 游戏服务健康检查：`http://localhost:3001`

如果要运行留言 API，需要先准备 PostgreSQL，再执行 `pnpm dev:progress-api`；没有数据库时不应修改游戏主流程。

## Codex 会话续接

- 用户级 Codex 配置将当前中转 Provider 标记为不支持远程压缩，Codex 应改用本地压缩；Provider 设置不能通过项目级配置覆盖。
- 配置变更需要重启 Codex 桌面端后生效。如果仍出现远程压缩断流，不要连续重试；在同一项目目录新开会话，先读 `.planning/monopoly-online/progress.md` 再继续。
- 长任务在 `.planning/monopoly-online/progress.md` 留下已完成事项、验证结果和下一步，避免依赖旧会话上下文。
