# 在线大富翁游戏设计

日期：2026-11-06  
状态：已获用户审核，进入实施

## 产品目标

开发一款浏览器大富翁游戏，每局支持 4-8 名玩家同时游玩。游戏是主要产品；另设公开的开发进度网站，展示项目进展并即时发布玩家提交的功能建议。玩法采用经典地产棋盘游戏的核心机制，同时使用原创品牌、地块名称、卡牌文本和美术资源。

## 美术方向

- 采用虚构现代城市主题，走轻松、清晰的桌游插画风格。
- 首版优先用网页组件/SVG 绘制可交互棋盘、地块标识和建筑图标；少量原创棋子与卡牌插画按需补充。
- 避免复制现有游戏的品牌、棋盘图和卡牌文案。

## 产品组成

### 游戏网站

- 创建房间并获得房间码；玩家输入房间码和昵称加入。原型阶段不要求注册账号。
- 房主选择简化版或复杂版；4-8 名玩家准备就绪后开始。
- 对局界面展示棋盘、当前玩家与待执行动作、玩家余额和资产、事件记录及可用操作。
- 玩家断线后可凭房间绑定的安全凭证重连，并恢复已确认的对局状态。

### 开发进度网站

- 公开展示路线图、里程碑、版本更新记录和已知问题。
- 功能建议提交后立即公开，不设置发布前审核队列。
- 服务端校验输入、限制请求大小、按 IP 限流并做基础垃圾内容过滤；提供授权人员隐藏/删除违规内容的能力。
- 原型阶段不收集邮箱等个人信息。

## 游戏模式与规则

两种模式共用一套确定性规则引擎和棋盘数据模型，通过配置区分，避免维护两套规则。时长为实测目标，不作保证。

### 简化版：目标 20-40 分钟

- 保留掷骰、移动、结算格子、买地或放弃、收付租金和结束回合等核心循环。
- 首版不开放玩家交易和抵押；使用紧凑的原创棋盘并简化建筑升级。
- 设置可配置回合上限；达到上限仍无人获胜时，按净资产结算（现金加资产价值，再扣债务），保证对局有结束路径。
- 通过实测调整棋盘大小、起始资金、回合上限和操作时限。

### 复杂版：目标 40-60 分钟

- 使用完整原创棋盘，包含地产组、租金阶梯、拍卖、建筑、事件卡、监狱、相同点数、玩家交易、抵押和破产。
- 最后一名未破产玩家获胜；设置安全回合上限，达到上限时按净资产结算。
- 小游戏延后到核心联机玩法稳定后，再作为独立、限时、由服务端裁定结果的棋盘事件加入。

资金、地产归属、回合和胜负均由服务端校验。客户端提交操作请求，不提交权威余额或结算结果。

## 首个可玩原型

首版完成标准是支持一局从大厅到结算的完整流程：

1. 创建/加入房间，限制 4-8 人，选择模式并开始。
2. 掷骰、移动、结算基础地产/事件格、买地或放弃、支付租金和结束回合。
3. 所有客户端同步棋盘、余额、地产归属、当前玩家和事件记录。
4. 断线重连后恢复对局，不丢失已确认状态。
5. 按模式规则结束并显示结果。

首版不包含账号、自动匹配、排行榜、观战、语音视频、付费、自定义棋盘和小游戏。

## 推荐技术架构

采用 TypeScript 单仓库：

- `apps/game-web`：React/Vite 游戏客户端。
- `apps/progress-web`：公开进度及功能建议网站。
- `apps/game-server`：Node.js + Socket.IO，负责房间、重连、操作校验和权威对局状态。
- `packages/game-rules`：确定性规则转换、模式配置、棋盘定义及单元测试，不依赖浏览器或传输层。
- `packages/shared`：共享类型与网络事件结构，并在网络边界做运行时校验。

服务端校验操作、应用规则变更、持久化已接受结果，再向对应房间广播。使用 PostgreSQL 保存公开建议和可恢复的对局快照/事件。首期预期通常仅有一局进行中，每局 4-8 人；仍保留房间隔离模型，但不做多房间横向扩展。初期运行单个游戏服务实例；暂不引入 Redis 或多实例编排。

在 Linux 云服务器使用 Docker Compose 部署，Nginx 负责 HTTPS 和站点/API/WebSocket 路由。Gitee 作为代码仓库，通过脚本部署指定版本。密钥只保存在服务器环境配置中。云服务商、域名和仓库地址待部署阶段确定。

## 可靠性与质量

- 服务端校验 Socket 事件和表单输入，限制字符串和请求体大小。
- 对创建/加入房间及功能建议限流；房间码随机生成并检查冲突。
- 校验回合所有权、操作合法性和资金变更约束。
- 每次接受操作后持久化，并制定废弃房间过期策略。
- 使用规则单测、服务端集成测试和 Playwright，覆盖 4-8 客户端、断线重连及建议即时发布。
- 分别统计 4 人局和 8 人局时长，再判断是否达到目标。

## 交付阶段

1. **基础工程**：单仓库、共享结构、规则状态模型、本地 Docker Compose、CI 检查。
2. **核心可玩版**：大厅、房间同步、地产循环、胜负结算、四客户端测试。
3. **模式完善**：简化版回合上限；复杂版拍卖、建筑、卡牌、监狱、交易、抵押、破产；覆盖 4-8 客户端测试。
4. **进度网站**：路线图、版本记录、问题列表、即时建议、限流和删除能力。
5. **云端测试版**：Gitee 部署、HTTPS、持久化数据库、备份、日志/健康检查及实测调优。
6. **后续内容**：依据反馈开发小游戏事件和视觉内容。

## 建议使用的 Skill

- `brainstorming`：实现前梳理和评审产品及玩法设计。
- `ui-ux-pro-max`：设计棋盘、大厅、响应式控件和进度网站。
- `playwright`：自动化多人浏览器流程和回归测试。
- `imagegen` 或 `gpt-image-2`：需要原创棋盘、卡牌或棋子位图时使用。
- 这是回合制 2D 游戏，无需专门游戏引擎 Skill；规则保持确定性并可用 TypeScript 测试。

## 测试版验收标准

- 房间支持 4-8 人且不同房间状态隔离。
- 非法、过期或非当前玩家的操作不能修改权威状态。
- 重连玩家回到原对局并取得最新状态。
- 两种模式均可完整结束；简化版有有界结算方式。
- 分别记录 4 人和 8 人局的实测中位时长并据此调优。
- 功能建议即时公开、受到限流保护，并可由授权人员删除。
- 云端两个网站使用 HTTPS；备份和健康检查流程有文档记录。
