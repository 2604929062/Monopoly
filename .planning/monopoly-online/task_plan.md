# 在线大富翁实施计划

## 目标
交付浏览器大富翁游戏与公开进度站，单局 4-8 人；首期通常只有一局进行中。游戏优先，进度站配套。

## 阶段
- [x] 0. 需求与设计：玩法范围、两种时长模式、现代城市美术方向、服务器规模假设已确认。
- [x] 1. 工程基础：pnpm 单仓库、两站点、Node/Socket.IO 服务、共享协议/规则包、本地启动和基础构建。
- [x] 2. 游戏垂直切片：房间大厅、4-8 人准备、掷骰/移动/买地/收租/回合同步/按净资产结束结算。
- [ ] 3. 规则扩展（进行中）：复杂版地产组、建筑、拍卖、事件卡、监狱、交易；破产、抵押、基础借贷和第一批扩展事件已完成，单人 AI 已完成基础可玩版本；赌场暂缓。
- [ ] 4. 恢复与持久化：PostgreSQL 快照/事件、断线重连、房间过期。
- [ ] 5. 进度站：路线图、更新、已知问题、即时公开建议及反滥用/删除能力。
- [ ] 6. 验证与云部署：多浏览器 4-8 人测试、性能观察、Docker Compose、HTTPS、Gitee 部署流程与备份。

### 本批次验证限制
- 本机没有 Docker/Podman CLI 或 PostgreSQL 客户端；未运行容器构建/Compose 校验，也未对留言 API 做真实数据库联调。
- 本地游戏站、进度站及游戏 Socket 服务健康；进度 API 因无本地 PostgreSQL 未启动。云端部署前需在服务器或装有 Docker 的环境实测。

### 并行接口约定
- 建议 API 监听容器内 `3002`，健康检查 `GET /health`，列表 `GET /api/suggestions`，新增 `POST /api/suggestions`（JSON `{ title, body }`）。
- PostgreSQL 使用 `DATABASE_URL` 环境变量；API 在启动时确保表已初始化，留言按创建时间倒序返回。
- 部署配置仅写 `deploy/`、`docker-compose.yml` 和 `docs/deployment.md`；不改应用源码或 workspace 清单。
- 监狱子任务拥有游戏规则、共享动作 schema、游戏服务和游戏 UI 文件；不得改部署或进度站文件。
- 建议 API 子任务拥有 `apps/progress-api/`、`apps/progress-web/` 和 workspace/lockfile；不得改部署文件。

- 两个 Vite 网站及游戏服务可本地启动。

## 风险/依赖
- 云端正式部署需要用户提供 Gitee 仓库地址、域名和 SSH/云平台访问方式；目前不阻碍本地开发。
- 本机没有 Docker；本地先用 Node 工具验证，容器部署在云服务器或安装 Docker 后验证。
- 时长目标须由 4 人和 8 人试玩数据调优。
